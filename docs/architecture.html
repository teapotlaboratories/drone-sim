Why QGC is not optional tooling

PX4 refuses to arm without a ground-station datalink, and NAV_DLL_ACT is left enforced deliberately — a real Pixhawk refuses too, so relaxing it in simulation would hide a real-flight failure. Stop this container and arming is denied. Verified in both directions.

04 The namespace trick that makes it work

Every container shares one network namespace and one /dev/shm, donated by the renderer (--ipc shareable, 2 GB). That is why 127.0.0.1 means the same thing to PX4, the agent and the renderer — PX4 dials loopback for both the agent and the simulator and reaches two different containers.

Sharing the network namespace ALONE is worse than sharing nothing

Fast-DDS discovers over UDP but delivers over shared memory when it believes the peer is same-host. Share the netns without /dev/shm and you get a full topic list and total silence. Measured, same subscriber, three ways:

no namespaces shared        51 topics   3 messages   OK
--network only              51 topics   0 messages   BROKEN
--network + --ipc           51 topics   3 messages   OK

Share both, or share neither. scripts/attach.sh shares both so the trap is unreachable.

By default nothing is published and the graph is reachable only from this host. Which switch you need is decided by one question: does the path carry UDP multicast?

Three things that look broken and are not

ros2 node list returns 0 for /fmu/* in every mode — the agent creates raw DDS participants with no ROS 2 node metadata. Topics and data are fine.

/fmu/out/* is BEST_EFFORT + TRANSIENT_LOCAL. A default RELIABLE subscription matches nothing and reads as silence on a healthy stack.

Frames are NWU, not ENU, and spawn Z is NED — negative is up.
