Frozen — historical record

This page is archived and preserved exactly as written. It is not maintained. It is the phase-gated build plan the project was executed against, written when it ran three parallel simulator stacks. Its phase order, its parallel-stack sequencing, its two-PX4-tree requirement and its container topology all describe stacks this repo no longer contains — the Gazebo baseline and Isaac Sim + Pegasus are retired, and the second PX4 tree existed only for Pegasus.

Read it as evidence, never as instructions. The setup commands, image tags, compose services, monorepo layout and task IDs on this page refer to things that have since been renamed or deleted. Its risk register, its version-coupling analysis and its evaluation metric definitions are preserved unchanged and are the parts still worth reading.

The repo today is one simulator: Unreal Engine 5.8 + Cosys-AirSim + PX4 SITL + ROS 2 Jazzy. What is still worth reading here: docs/history/README.md · task-ID renames: id-map.md · the repo: README.md

Phase 0 — Environment & version lock

Goal. Reproducible pinned toolchain; every component passes its own smoke test; versions.lock committed.

Phase 1 — Lane A baseline: GPS navigation + offboard control

Goal. Deterministic headless PX4 + Gazebo SITL with a ROS 2 offboard controller flying GPS waypoint missions in lockstep, recorded to MCAP, CI-gated under 10 minutes.

Exit criteria

  • Automated test: take off → 4-waypoint square → land, SR = 100% over 10 seeded runs
  • MCAP artifact uploaded per CI run
  • Real-time-factor floor asserted so lockstep desync surfaces rather than hiding

Work items

  • Offboard node using TrajectorySetpoint, OffboardControlMode, VehicleCommand
  • sim.launch.py with use_sim_time:=true; freeze topic and namespace conventions now — they must survive to the aircraft unchanged
  • Seeded scenario runner; rosbag2 → MCAP recording

Known trapLockstep desync trips PX4 failsafe. Set param set-default COM_OF_LOSS_T 15. In CI, retry twice and assert the RTF floor — retry alone masks the real defect.

Phase 2 — Perception, mapping, obstacle & collision avoidance

Goal. Depth/Lidar-equipped X500 builds a local map and flies collision-free through cluttered worlds under EGO-Planner.

Exit criteria

  • Zero collisions across 20 seeded cluttered-world runs
  • Reach-goal success ≥ 80%
  • Replan latency logged per cycle

Work items

  • Mapping: isaac_ros_nvblox on GPU, OctoMap as the CPU/CI fallback
  • Port EGO-Planner to ROS 2 (use the EGO-Swarm repo with drone_id=0); bridge trajectory output to PX4 offboard
  • Build the obstacle scenario library with fixed seeds

Effort 15–20 engineer-days, dominated by the planner port · Unlocks obstacle avoidance collision avoidance

GateIf the EGO-Planner ROS 2 port slips more than a week, run the planner in a ROS 1 bridge container as a stopgap and keep the schedule. Do not let the port block Phase 3.

Phase 3 — VLM vision-navigation + GPS-denied VIO

Goal. Slow VLM target-generator plus fast EGO-Planner tracker against a dev-time vLLM Qwen3-VL endpoint; 2D waypoint → depth back-projection → 3D goal. GPS-denied flight on cuVSLAM feeding EKF2.

Exit criteria

  • VLM-commanded SR ≥ 50% (SR@5m) over 20 episodes
  • VIO-only hover drift < 1 m over 60 s
  • End-to-end target-generation latency budget documented with p50/p95

Work items

  • vlm_client node against an OpenAI-compatible endpoint; message contracts + watchdogs
  • Depth back-projection with camera intrinsics — use sensor depth, not VLM-estimated depth (Fly0's ablation shows SR falling 70.43% → 56.47% without it)
  • cuVSLAM → /fmu/in/vehicle_visual_odometry; tune EKF2_EV_CTRL, EKF2_HGT_REF, EKF2_EV_DELAY, EKF2_EV_NOISE_MD, EKF2_EVP/EVV/EVA_NOISE. Stream 30–50 Hz or EKF2 will not fuse.
  • GPS-dropout injection; Lane B photoreal scenes via Pegasus on the v1.14.3 tree

Effort 20–28 engineer-days · Unlocks vision-based navigation VLM experimentation

GateIf the Isaac Python split blocks progress more than three days, demote Isaac to a pure DDS sensor source and keep all application logic in system Jazzy. Watch for EKF2 drift-to-origin — it signals frame or parameter misconfiguration, not a VIO quality problem.

Phase 4 — Benchmark reproduction, onboard VLM, HITL and flight

Goal. Reproduce AerialVLN/OpenFly-style evaluation; port the VLM stack onboard the Orin NX; PX4 HITL then real X500 flight.

Exit criteria

  • AerialVLN SR within ~10 absolute points of Fly0's 70.43%, or a written gap analysis
  • Onboard decision latency ≤ 1 s (OnFly achieves ≈0.81 s on Orin NX)
  • One successful real GPS-waypoint flight and one VLM-navigation flight

Work items

  • UE 5.5 + Cosys-AirSim from source at a pinned commit
  • AerialVLN / OpenFly scene and instruction ingestion; batch runner emitting SR, SPL, NE, OSR, CR
  • jetson-containers TensorRT-LLM serving Qwen3-VL-4B-AWQ — AWQ on the LLM, FP16 ViT, cached visual features, KV-cache reuse, CUDA graphs
  • HITL bring-up on the Pixhawk 6C; written flight-test cards

Effort 25–35 engineer-days, Lane C is the long pole · Unlocks benchmark parity sim-to-real

§ 6 · LAYOUT

Monorepo structure

drone-sim/
├─ versions.lock          # pinned SHAs/tags — PX4 ×2, px4_msgs, Isaac, Pegasus, AirSim, planner
├─ .repos                 # vcstool manifest; prefer over submodules for third-party
├─ docker/                # per-service Dockerfiles + compose files
├─ ros2_ws/src/
│  ├─ interfaces/         # TargetWaypoint, TrackerGoal, VlmQuery/Result
│  ├─ bringup/            # sim.launch.py · real.launch.py · shared includes
│  ├─ sim_bringup/        # Gazebo / Isaac / AirSim spawn + scenario loading
│  ├─ perception/         # cuVSLAM glue, nvblox glue, depth processing
│  ├─ state_estimation/   # EKF2 param sets, EV odometry publisher
│  ├─ planning/           # ego_planner_ros2 port + PX4 offboard bridge
│  ├─ control/            # offboard setpoint node
│  ├─ vlm_client/         # slow target generator + fast tracker
│  └─ evaluation/         # SR · SPL · NE · OSR · CR + batch runner
├─ scenarios/             # seeded worlds, AerialVLN/OpenFly instruction ingest
└─ configs/               # per-lane YAML overrides

Launch architecture

One bringup package, two entry points sharing common includes. sim.launch.py sets use_sim_time:=true; real.launch.py sets it false. Topic names are identical across both: /fmu/*, /vlm/target, /planner/trajectory. Nothing in the application layer branches on which lane is running.

Interface contract for the VLM split

TargetWaypoint.msg
std_msgs/Header               header
geometry_msgs/PointStamped    goal_3d
float32                       confidence
uint8                         source        # VLM | TRACK
builtin_interfaces/Duration   ttl           # watchdog horizon
  • Target generator publishes at ~0.3–0.5 Hz; tracker consumes and republishes TrackerGoal at 50 Hz
  • On ttl expiry the tracker holds position — it never blocks waiting on the VLM
  • VLM error or timeout retains the last valid goal, producing the object-permanence behaviour Fly0 relies on

Dependency management

vcstool .repos for third-party sources; submodules only for forks you own. Renovate or Dependabot watches the lockfile. The branch-match rule is non-negotiable: px4_msgs branch equals the firmware release branch.

§ 12 · SUMMARY

Standing orders

  1. Lock versions before writing code. Two PX4 trees, two Python runtimes. This is the architecture, not a workaround.
  2. Freeze topic and namespace conventions in Phase 1. They must reach the aircraft unchanged; renaming later invalidates every recorded bag.
  3. Never let the tracker block on the VLM. The ttl watchdog is a safety property, not an optimisation.
  4. Use sensor depth, not VLM-estimated depth. Fly0's ablation shows a 14-point SR drop without it.
  5. Assert the real-time-factor floor in CI. Retries alone turn desync into an intermittent green build.
  6. Parameterise the success threshold. 5 m and 20 m are both correct depending on the benchmark.
  7. Gate flight on HITL passing the identical SITL suite. No exceptions, no shortening.
