01 What this task had to prove

C-01 established the tag exists by querying the registry for ~17 KB. That is not the same claim as the image works, and the distinction is written into versions.lock deliberately. Two things were carried as unverified:

  • The Ubuntu 22.04 base — read from the registry's config blob, never from a pulled image. It is architecturally load-bearing: ROS 2 Jazzy has no jammy packages, so it forces Lane C into at least two containers.
  • The size — measured compressed. The D-04 storage decision (internal NVMe, because the 7 TB external is a 7200 RPM spinning disk) was made on that figure.

1 · --ue-root is mandatory, not advisory

Cosys-AirSim's build.sh on the 5.8 line supports it and uses the engine's bundled clang. There is no system clang in this image, so a build that omits --ue-root has no compatible compiler at all — it will not degrade gracefully.

The bundled toolchain is clang 20.1.8, exactly what upstream is documented to have built v3.4.1 with — so the ABI-mismatch risk that made the UE5.5 line awkward does not arise here, provided the flag is used.

2 · dev-slim ships an installed engine

Setup.sh and GenerateProjectFiles.sh are absent; UnrealBuildTool.dll is present. Plugin builds go through UBT. Any upstream instruction that assumes a source checkout needs translating.

05 The plugin build — and the one-second failure that produced D-04

./build.sh --ue-root on the stock engine image died in one second:

++ which cmake
+  CMAKE=

The tempting move, and why it was wrong

apt install cmake in a running container would have worked and been unreproducible — exactly what the reproducibility goal exists to prevent. So every tool the scripts invoke was enumerated in one pass rather than one crash at a time.

Tools
needed by build.sh/setup.shclang cmake gcc make rsync unzip wget zip
already in dev-slimmake unzip zip gcc g++ git curl python3 tar patch pkg-config

That is docker/lane-c.Dockerfile — engine pinned by digest (not the moving dev-slim-5.8 alias), plus those three, +33 MB on a 57.4 GB base. clang is deliberately not installed: a system clang would recreate the ABI mismatch against UE's linker that the UE5.5 line documented, and build.sh itself refuses --ue-root with --gcc because the bundled toolchain is Clang-only.

A version-recording layer that silently recorded nothing

The Dockerfile's first version extracted the engine version with an inline Python f-string containing escaped quotes — a SyntaxError here. The layer succeeded anyway, because the redirect still created the file, and wrote ue_engine= empty.

A version-recording step that silently records nothing is worse than none: it looks like evidence. Same class as the build script that printed BUILD OK after make exited 2. Fixed with set -eux and non-empty assertions, and verified by breaking it — the guard fires with FATAL: a version probe produced an empty value.

06 The plugin compiles against the engine

Terminology correction

Earlier notes said "package". That is a different, heavier job (RunUAT, producing a distributable binary). What was run is compiling the editor target — building the AirSim plugin's C++ against Unreal's engine headers.

Why this is the step that matters. Everything before it proved a standalone library compiles: libAirLib.a includes no Unreal headers and would build with no engine present at all. The AirSim plugin is different code — it subclasses engine types and calls engine APIs. An Epic rename or signature change between 5.5 and 5.8 could only surface here.

A false alarm, checked before reporting

ldd on the plugin module says 12 unresolved libraries, which looks alarming. All twelve are engine modules — libUnrealEditor-Core.so, -Engine.so, -RenderCore.so, -RHI.so — which live in the engine tree, not on the host. Re-run inside the image with the engine lib path: zero unresolved. Expected for a UE plugin, not a defect.

One more way the 5.8 line is coherent

Blocks.uproject declares EngineAssociation: 5.8, an exact match — no convert-in-place prompt. At the 5.5 tag it declared 5.4, which triggers that prompt and is a documented point where a user hit a failed compile.
