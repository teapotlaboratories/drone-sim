01 The claim that needed testing

The gate passes SR 10/10 — but the seed only moved the spawn point, and PX4 sets its local frame origin wherever the estimator initialises. In an empty world the flight is unchanged. "Ten seeded runs" was closer to ten repeats. The plan was to reach the genuinely stochastic part, sensor noise, with gz sim --seed.

Conclusion

Two runs with the same seed differ by as much as two runs with different seeds. Not one sample matches, at identical instants of simulated time. gz sim --seed does not control the sensor noise here. The plumbing was reverted — it bought nothing measurable and would have implied control the stack does not have.

05 Three traps worth keeping

A plugin in the world SDF

Makes Gazebo load only that plugin, dropping Physics, UserCommands and SceneBroadcaster. Six topics, no scene/info, no vehicle, PX4 times out — and gz sdf -k calls the file Valid. The plugin belongs in a copy of PX4's server config.

enable_wind

Upstream x500_base does not set it, so without the model overlay the wind applies to nothing and the flight looks entirely normal.

Zero wind is not the stock baseline

The overlay changes physics even at 0 m/s — 0.16 m mean error stock against 0.358 m on the overlay, because enable_wind adds air-relative drag the stock model has none of.

The bound is load-bearing

At 8 m/s the disarmed vehicle is blown 416 m before it can arm; the estimator gives up and the run fails in wait_for_fcu — a harness failure wearing a controller failure's costume.
