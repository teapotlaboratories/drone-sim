01 Conventions frozen first

The plan is explicit (02_development_plan.md:252): freeze topic and namespace conventions in Phase 1, because they reach the aircraft unchanged. Every decision was taken against the running stack, not from memory.

Namespace

Bare /fmu/* behind a px4_ns parameter defaulting to empty, so a second aircraft is configuration rather than a refactor.

QoS — the false negative

PX4's /fmu/out publishers are BEST_EFFORT + TRANSIENT_LOCAL. A default subscription matches nothing and the node sees zero messages against a perfectly healthy stack.

Frames

ENU/FLU outside, NED confined to one tested function. A double conversion is the identity on some axes and a sign flip on others — the vehicle accepts the command and flies into the ground.

NaN, not 0.0

TrajectorySetpoint documents NaN as "do not control this state". A zeroed velocity array commands zero velocity, fighting the position controller.

02 The arming investigation

The node reached offboard mode instantly, then sat in arm until it timed out. PX4 said only Arming denied: Resolve system health failures first — the specific reason goes to the MAVLink log, i.e. to the ground station a headless stack does not have.

The fix, and the one rejected

Rejected: setting NAV_DLL_ACT 0 to switch the check off. It worked, and it was wrong — requiring a ground-station datalink before arming is correct, and a config that arms without one is not a config to carry toward hardware.

Shipped: a real QGroundControl service. Verified causally in both directions — QGC running: arms and flies. QGC stopped: arming denied.

03 18570, not 14550
