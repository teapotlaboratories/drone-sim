A Checker
That Can Fail

The rule said tear down and verify; there was no command to do it. Writing one produced four separate ways a checker reports a clean machine that isn’t — each found inside the checker itself.

01 The design goal was that it can fail

After a branch whose worst defect was a guard that never executed while its test reported green, a verifier that only ever prints “none” is worthless. Run against a live stack:

sim-unreal  Up 50 seconds
pgrep -x UnrealEditor            STILL RUNNING: 931470
pgrep -x px4                     STILL RUNNING: 931985
Xvfb on :77                      STILL RUNNING: 931530 Xvfb :77 -screen 0 1920x1080x24 …
GPU compute apps                 931470, 4569 MiB
exit 1

The GPU holder is the renderer’s own PID — a cross-check that falls out for free. --down on that same stack then returned all-clear, exit 0.

02 Four ways this checker lied — during its own implementation

The off-by-one, verified rather than reasoned

comm is truncated to 15 characters, so UnrealEditor-Cmd (16) becomes UnrealEditor-Cm. I wrote UnrealEditor-C — 14. Tested with a real binary of that name: comm reads UnrealEditor-Cm, my pattern matches 0, the correct one matches 1. A leaked UnrealEditor-Cmd holding GBs of VRAM would have printed none.

03 Two more the review caught

A teardown that ran the bring-up first

A missing settings file or a stale exported SPAWN would kill --down with a message about spawns, stack still up — and write sim/ue5/.settings.run.json as a side effect of a command meant to remove things. Guarded, and tested with the settings file moved aside and SPAWN=999,999,999 exported.

The claim outran the checks

“Nothing of ours is left running” — but pgrep -x is blind to scripts (comm=bash) and runners (comm=python3), which is exactly the two-hour incident: containers re-created afterwards by a detached bring-up. --down now walks /proc for one, excluding its own ancestors since this script’s cmdline also says sim_up.sh.

04 What it replaces

~50 lines of hand-verification caveats in .ai/AGENTS.md, kept only because there was no command. They are now code with tests — 171 total, ten covering this command, including that it can fail.

The pattern worth keeping

Every defect here was in a checker, and none failed loudly. An aborted report looks clean. An off-by-one pattern prints “none”. A substring assertion passes. A printed warning with no verdict change exits 0.
