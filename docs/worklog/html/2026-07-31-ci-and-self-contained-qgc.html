01 Why CI is two tiers

The plan asked for CI that builds the image and runs the gate under ten minutes. Measured against a GitHub-hosted runner, that is arithmetic, not effort:

Hosted runnerLane A needs
Disk~14 GB freeimage is 12.6 GB
Build—20–40 min
CPU2 vCPUgate asserts RTF ≥ 0.95
Gate—~19 min for 10 seeds
The line that decides it

On two cores PX4 and Gazebo miss the real-time floor on the hardware, not the code. The only way to green it would be lowering the floor — removing the assertion that caught this box's nested-Docker deficit in the first place.

03 Review of the CI found a real privilege problem

Write token

The job inherited the repo default GITHUB_TOKEN, which is write. A job running pytest and grep had write access to the repository. Now contents: read, set explicitly — this file is the template tier 2 and D-05 get copied from.

Moving tags

Actions were pinned to @v4 / @v5. That contradicts this project's own rule that a branch is not a pin — learned when the XRCE agent's branch pin evaporated, and again when QGC's latest channel had to be repinned. Both are commit SHAs now.

04 QGC made self-contained

QGC was a 180 MB bind mount the user had to fetch first, on the reasoning that CI has no use for it. That reasoning was wrong: PX4 will not arm without the datalink, so a stack that cannot fly until someone runs a download script is not "reproducible from the repo alone".

Two silent no-op edits

Two str.replace calls matched nothing and did nothing — the openbox block sits between the copy and the exec. Result: QGC_APPIMAGE: unbound variable and an exec pointing at a deleted file. Only running the container surfaced it. Edits now abort on a non-match.

05 Decision: local CI is accepted

D-07 defers the automated flight gate. Two blockers — hosted runners cannot do it, and a self-hosted runner on a public repo lets any fork's pull request execute code on this machine, the one holding SSH keys, the netbird tunnel and the 7 TB drive.

The substitute

./scripts/run_local_ci.sh --gate — one command, the same tier-1 checks CI runs plus the flight gate. It warns when the working tree is dirty, and distinguishes a fast-checks pass from a real gate run so neither gets quoted as the other.

What it costs, plainly: a controller regression is caught when someone runs the gate, not when it lands.
