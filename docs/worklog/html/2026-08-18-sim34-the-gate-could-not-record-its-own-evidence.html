The tool that exists to produce evidence recorded 40 videos of the wrong thing and reported success. Fixing it took three review passes — and two of the worst findings were defects introduced while fixing the previous one.

01 The tool that could not produce its own evidence

Hard stop 5 requires the chase camera on every flight test, because a camera bolted to the aircraft can never show the aircraft. The first full 40-seed gate returned chase_video: None on all 40 runs, while the 40 videos it did write were the vehicle camera — the exact view the rule was written to reject — reported alongside video_written: True.

Nobody owned the coupling

Chase recording needs an Xvfb screen, which only sim_up.sh --display creates. Remembering that was each caller's job. run_gate.py forgot — silently, because chase_available() simply returns false and the recorder never starts.

02 The fix is the coupling, not the flag

restart_stack now derives --display from the same SIM_CHASE_VIDEO that run_flight reads, so “asked for chase but the renderer has no display” is unrepresentable rather than a per-caller mistake. Chase is on by default; --no-chase opts out and says so, in the console and in the JSON.

03 Three review passes

Pass 2 — the fix was worse than the bug

The stale-video unlink was unconditional, so it ran with chase disabled too. The same commit added --no-chase to run_local_ci.sh over the same seed numbers — so ./scripts/run_local_ci.sh --gate would have deleted square-10m-seed1..10-chase.mp4, including the two files this branch cites as its own verification, from out/, the symlink to the 7 TB archive. Unrecoverable.

Verified the destructive way: ran a --no-chase gate over seed 1 and confirmed the existing 42.9 MB video survived byte-identical (md5 b3dc3625164a before and after) — not by re-reading the guard.

Pass 3 — the abort re-created the loss it prevented

The three-strikes abort added in pass 2 called sys.exit() before the summary is written. A 40-seed run that flew 37 seeds over two hours and then hit three bring-up failures would discard every completed flight — precisely the loss the try/except cites as its reason for existing. Now it records the aborting seed, breaks, and writes the report.

A test that failed on its first run, correctly

test_only_one_truthiness_literal_survives was written to lock in the new _env_true() helper. It failed: SIM_NO_VIDEO carried two more copies of the same literal. The drift the helper exists to prevent was already present.

04 What the pattern says

Every pass found something real, and the two worst were self-inflicted. The pattern is specific: each fix touched the path that decides what counts as evidence, and a mistake there does not fail loudly. It produces a confident report about a file that is wrong, missing, or someone else's.

Which is the original bug restated. SIM-34 was never “the flag wasn't set”. It was a tool that reported success while recording the wrong thing.
